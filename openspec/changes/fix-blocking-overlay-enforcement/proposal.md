# Proposal

## Why

In `focusGuard`, when a user starts a focus session, the React Native UI and foreground notification indicate active enforcement, but third-party applications (e.g., YouTube, Chrome) are never blocked and the lock overlay never renders. This critical defect occurs because the native `FocusAccessibilityService` queries an empty database (`/databases/focusguard.db`) rather than the `expo-sqlite` database path (`/files/SQLite/focusguard.db`), has no in-memory session synchronization from the module layer, contains improper `WindowManager.LayoutParams` flags, and lacks self-overlay/empty event filtering. Fixing this now restores the fundamental value proposition of the app: reliably enforcing focus lock on Android devices.

## What Changes

- **Synchronous In-Memory Session Synchronization**: Update `FocusEnforcerModule` to broadcast `endsAtEpochMs` directly to `FocusAccessibilityService` and `LockOverlayWindowManager` in memory during `startFocusLock` and `stopFocusLock`.
- **Database Path Alignment**: Update native SQLite helpers (`NativeDbHelper` and `FocusDatabaseHelper`) to resolve the exact SQLite database file generated by `expo-sqlite` (`files/SQLite/focusguard.db`) as a fallback persistence mechanism.
- **Lock Overlay Window Management Hardening**: Correct window flags in `LockOverlayWindowManager` (`TYPE_ACCESSIBILITY_OVERLAY`, full-screen layout flags, modal touch capture, avoiding double-attachment crashes) and add proper logging.
- **Accessibility Event Filtering & Debouncing**: In `FocusAccessibilityService`, ignore blank/null packages, ignore self-package overlay events, and retain previous target state to prevent screen flashing or instant dismissal.

## Capabilities

### New Capabilities
None.

### Modified Capabilities
- `lock-overlay`: Ensure reliable window presentation, lifecycle management, and touch interception without crashes or silent failures when active focus sessions are triggered.
- `app-detection-allowlist`: Ensure the Accessibility Service receives real-time session state via memory and aligned SQLite persistence, correctly evaluates target package transitions, and suppresses false dismissals.

## Impact

- Native Android module files in `focusGuard/modules/focus-enforcer/android/`:
  - `FocusAccessibilityService.kt`
  - `FocusEnforcerModule.kt`
  - `NativeDbHelper.kt`
  - `FocusDatabaseHelper.kt`
  - `LockOverlayWindowManager.kt`
- No breaking changes to the TypeScript / React Native API contract (`FocusEnforcer.startFocusLock`, `FocusEnforcer.stopFocusLock`).
